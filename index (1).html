    ~ / projects / strauss-car-advisor / README.md

    Strauss Car Advisor

    statuslivetests179 passinglangTypeScripthackathonOpen Code AI 2026

    A Hebrew chatbot that answers a question employees can't easily work out alone: what happens to my net pay if I swap my company car, go electric, or give the car up?

    Live site ↗Code

    Problem

    Value-of-use tax, pension, credit points: the net effect of a car change is hard to compute, and an LLM that does arithmetic on its own gets numbers wrong.

    Approach

    • The model never does the math. It understands the request and calls tools; a pure engine computes every figure.
    • Human in the loop. When only the company has the answer, the bot asks a rep, shows what it already computed, and resumes.
    • Transparency. A comparison card breaks the net-pay difference into its causes, ranks alternatives and previews the next payslip.

    Architecture

    strauss-car-advisor/
├─ apps/web         # Next.js: employee UI, /rep, API
├─ packages/engine  # pure net-pay math, zero LLM deps
├─ packages/agent   # tools, prompts, provider failover
├─ packages/data    # SQLite: 77,988 cars + chat store
├─ config/          # rules & catalog as JSON (zod)
└─ scripts/         # excel → config, image fetch

    Engineering

    • Automatic failover across 7 LLM providers (Gemini, Claude, Cohere and more) when quota runs out
    • ID numbers masked before storage and before reaching a model; rate limiting on every endpoint
    • Payslip reading: the model reads printed figures only, code computes, the employee confirms
    • Docker, a Render Blueprint, and GitHub Actions CI on every pull request
